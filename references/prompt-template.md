# 通用网页 UI 设计提示词模板

用于将具体项目需求交给设计或编程助手。填写已知事实；删除不适用的字段。`【待补】` 只留给确实会影响结果的信息，不要把示例业务、按钮文案或六套配色预先填入。

```text
请为以下项目设计或改造网页 UI。先根据页面任务和真实内容决定结构与视觉方向，再给出可实施的结果；不要套用固定的营销页模板。

【项目】
- 产品／组织与用途：【已知事实】
- 页面类型与页面要完成的任务：【按实际填写】
- 目标用户及使用情境：【已知事实】
- 必须呈现的内容、数据和功能：【已知事实】
- 用户实际需要执行的操作及文案：【已知事实；没有则写“无明确操作”，不要自行添加促销按钮】
- 品牌规范、现有设计系统及不可改动项：【已知事实或“无”】
- 现有页面、参考图或希望呈现的气质：【链接、附件或文字描述】
- 配色偏好与探索范围：【品牌色／参考色／允许的新色相；想看几套方案】
- 技术栈与可用素材：【如需实现则填写】
- 交付方式：【设计方案／页面规格／直接改代码】

【设计要求】
1. 先明确页面目标、用户优先要看到的信息及内容顺序。根据页面类型安排导航和区块；不预设 Hero、卡片、表单或主按钮一定存在。
2. 解释版式、字级、留白、颜色、图像、形状与动效如何共同支持该目标。保留现有品牌约束；参考图只用于提炼视觉原则，不照搬具体页面。
3. 定义适合本项目的语义设计变量和关键组件。把六组参考色视为起点，可跨组混搭、调整明度和饱和度、引入新色相；同时考虑品牌色和页面素材。不要只返回原始六套，也不限制为三种颜色。若我要求配色探索，先给出有明显区别的多套方向，再筛选适合本页面的方案；说明每套的背景、文字、重点色、撞色关系和使用位置。参考 references/color-lab.md 的方法，继续创造新组合，不把其中的示例当作固定菜单。
4. 对页面实际存在的交互给出相关状态与反馈；根据内容决定宽屏和窄屏布局。检查实际相邻颜色的可读性，以及键盘焦点和触控使用。
5. 如果能编辑项目，直接实施并验证页面；如果只交付方案，给出足够具体的结构、变量和组件规格，供实现者直接使用。

【输出】
- 页面目标与必要假设
- 内容结构和视觉方向
- 设计变量与实际需要的组件规格
- 响应式及交互说明
- 已验证的结果；若修改代码，列出文件与验证方式
```

如果用户只要求配色，可输出 12–20 套不同方向的候选，重点展开其中 3–5 套的语义变量、用色位置及对比度检查；数量以用户要求为准。如果只要求实施，不重复输出长篇设计提案。
